## Findings

### HIGH

**1. `service/PlaceholderService.java` (~L123–127) — Anthropic call has no system prompt.**
The `MessageCreateParams` is built with `.model()`, `.maxTokens()`, and
`.addUserMessage(prompt)` but no `.system(...)`. CLAUDE.md states explicitly: *"Every
LLM API call (Anthropic or OpenAI) must include a system prompt. A call without a
system prompt is a HIGH finding."* Contrast `RecommendationService.java:106`, which
correctly sets `.system(SYSTEM_PROMPT)`. This call runs on every login
(`regenerateAsync`) and in the daily scheduled job, so it is a live guardrail gap.

**2. `mcp/SpotifyMcpTools.java` (`get_recommendations`) + `service/RecommendationService.java` (L129–144) — MCP read-only invariant broken.**
`recommend()` auto-saves resolved tracks to the user's Spotify playlist
(`getOrCreatePlaylist` + `addTracksToPlaylist`). Because `get_recommendations` is
exposed as an MCP tool, and `/mcp/**` is CSRF-exempt in `SecurityConfig.java:74`, a
state-changing write is now reachable via the CSRF-exempt endpoint. The in-code comment
(L129–134) acknowledges this and says it *"must be removed before any deployment."*
This defeats the exact safety argument the CSRF exemption relies on (MCP tools are
read-only). The reflection-based read-only test guards the MCP method surface but not
transitive service side effects, so the build does not catch this.

**3. `config/SecurityConfig.java` (L74, L90) — H2 console is CSRF-exempt and `permitAll`.** *(human-review-protected file)*
`/h2-console/**` is added to `csrf().ignoringRequestMatchers(...)` alongside `/mcp/**`,
but the exemption comment (L66–73) only justifies the read-only `/mcp/**` path. The H2
console is a state-changing endpoint (arbitrary SQL) and is also `permitAll()` at L90.
This contradicts the documented principle that only read-only `/mcp/**` may be
CSRF-exempt. The project uses Postgres in dev and prod (CLAUDE.md), so the console
appears to serve no purpose here; if it is ever enabled in a deployed profile this is
directly exploitable. Recommend removing it or strictly gating behind a dev-only profile.
Flagging for human review as this file is change-protected.

**4. Untested changed code (test coverage gap — HIGH per review policy).**
The following changed source classes have **no** corresponding test, leaving business
logic and a fail-closed security path unverified:
- `controller/AuthController.java` — `/api/auth/me` 401-vs-authenticated branch and DTO mapping.
- `controller/UserController.java` — three endpoints; `@Min/@Max` validation and `timeRange` default.
- `controller/PlaylistController.java` — pagination constraints and delegation.
- `service/UserService.java` — `findBySpotifyId` fail-closed `404 ResponseStatusException` (security-relevant) is untested on both branches.
- `service/PlaylistService.java` — delegation / argument pass-through untested.

(See "Test coverage gaps" below for the full inventory including MEDIUM/LOW config gaps.)

**5. `.github/workflows/auto-implement.yml` (L73) — broad `Bash(git push *)` grant.**
A trailing-wildcard `git push *` lets the write-scoped Auto-Implementer push to any ref
(including `master`/`devel`), not just `fix/*` branches. This violates least privilege
for an agent whose only mandate is opening PRs. It is marked TEMPORARY but has no removal
date. Recommend scoping to the fix branch pattern.

### MEDIUM

- **`config/WebClientConfig.java` (~L134)** *(protected)* — `Long.parseLong(retryAfter)` is
  unguarded. Per RFC 7231 `Retry-After` may be an HTTP-date; a non-numeric value throws
  `NumberFormatException` inside the reactive status handler, converting a recoverable 429
  into an unexpected error (not fail-safe).
- **`controller/RecommendationController.java` (~L44–47)** — the `/quick` **GET** endpoint
  triggers the auto-save side effect (finding #2). Exposing a mutating operation behind a
  CSRF-exempt, cacheable/prefetchable GET undermines CSRF protection; state changes should
  not be reachable via GET.
- **`service/RecommendationService.java` (L92)** — `getTopTracks("medium_term", 10).getItems()`
  is not wrapped in try/catch (unlike `ChatService`), and `getItems()` can NPE on a null page;
  contradicts the class Javadoc's "all external calls are individually fail-safe" claim.
- **`service/SpotifyApiService.java` (~L266–286)** — `getOrCreatePlaylist` dereferences
  `getProfile().getId()`, `getPlaylists(...).getItems()`, and the created-playlist `.block()`
  result with no null guard; empty bodies produce NPEs rather than a fail-closed error.
- **`service/PlaceholderService.java` (L173)** — `@Scheduled(cron = "0 0 3 * * *")`
  `refreshAllPlaceholders()` runs a Spotify + Anthropic round-trip per user unconditionally,
  with no enable flag (unlike the RAG job, which is gated on `ragEnabled`).
- **`controller/UserController.java` (L34, L41)** — `timeRange` is a free-form `String`
  forwarded to Spotify unvalidated; only `short_term|medium_term|long_term` are valid. Should
  be constrained (enum / `@Pattern`) to fail safe on bad input.
- **`.github/workflows/code-review.yml` (L57, L65)** — `Bash(git commit *)` uses a trailing
  wildcard (passes arbitrary flags), and the "Push report" step runs raw `git push origin devel`
  outside the scoped agent. Combined with `contents: write` this is a broader push surface than
  the report-only intent requires.
- **`.github/workflows/code-review.yml` (report guarantee)** — if a run fails before writing a
  report file, no report artifact is produced. CLAUDE.md's auditability principle requires a
  report even when findings are empty.
- **`.github/workflows/auto-implement.yml` (L74)** — `Bash(grep *)`, `Bash(echo *)`, `Bash(ls *)`,
  and `Bash(gh pr create *)` are broad wildcard grants where narrower commands would suffice.
- **Missing Javadoc on classes/public methods** (CLAUDE.md commenting convention):
  `AuthController`, `PlaylistController`, `UserController` (class + all public methods),
  `AppUser` (class).

### LOW

- **`config/SecurityConfig.java`** — L118 uses magic literal `200` instead of `HttpStatus.OK.value()`;
  L121 `frameOptions.sameOrigin()` is applied globally rather than scoped to the H2 path.
- **`config/WebClientConfig.java`** — the anonymous/HTTP-session fallback branch is documented as
  "never exercised in production" but nothing enforces that assumption.
- **`config/OAuth2SuccessHandler.java`** — `principal.getAttribute("id")` (spotifyId) is used as the
  entity key with no null/blank check; `embeddingService` is injected but unused (dead wiring for a
  disabled feature).
- **`config/InviteOnlyAuthenticationFailureHandler.java`** — logs `exception.getMessage()` at INFO on
  every OAuth failure (log-hygiene).
- **`config/EmbeddingConfig.java`** — uses raw `${OPENAI_API_KEY:}` env placeholder rather than a
  namespaced property, inconsistent with `anthropic.api-key` convention.
- **`service/ChatService.java` (L166/173)** — `getTopTracks(...).getItems()` NPE risk on null page
  (absorbed by the surrounding `catch (RuntimeException)`, hence LOW).
- **`service/SpotifyApiService.java` (~L346–374)** — `resolveToSpotifyTrack` interpolates raw
  Claude-supplied `trackName`/`artist` into the `q` query param; URL-encoded so not an injection risk,
  but odd characters can silently break matching (correctness).
- **`service/EmbeddingService.java` (~L411–421)** — `rs.getTimestamp("last_updated").toInstant()` will
  NPE on a SQL NULL; minor since the column is set on upsert. (RAG is correctly disabled by default.)
- **`util/PlaylistNameUtil.java`** — missing class and public-method Javadoc.
- **`controller/AuthController.java`** — magic `401`/`ResponseEntity.status(401)`; `findBySpotifyId`
  result passed to `UserProfileDto.from(...)` with no not-found handling.
- **`controller/PlaylistController.java`** — `@PathVariable String id` forwarded to Spotify with no
  format validation.
- **`resources/schema.sql`** *(protected)* — `chat_log` has no index on `user_id` (queried per-user);
  `chat_log.created_at` has a default but no `NOT NULL`; `chat_log.user_message`/`response` and
  `app_user.email` are stored plaintext (PII/sensitive content, informational — no retention note).

**Positives confirmed:** tokens are stored only in `oauth2_authorized_client` (BYTEA), not in
`AppUser`/`ChatLog` (compliant); all Spotify calls `.block()` at the service layer; MCP tools other
than the `get_recommendations` side effect are read-only; `AnthropicConfig` fails closed on a missing
key; RAG/EmbeddingService is correctly disabled unless `OPENAI_API_KEY` is set; `SpotifyLogoutHandler`
and `CsrfCookieFilter` correctly fail safe; both workflows set an agent git identity (auditability).

## Recommended actions

Prioritised — HIGH first:

1. **Add a system prompt to the `PlaceholderService` Anthropic call** (`.system(...)` on the
   `MessageCreateParams` builder, ~L123). Direct HIGH violation of the mandatory system-prompt principle.
2. **Remove the auto-save side effect from the `get_recommendations` MCP path**, or move auto-save out
   of `RecommendationService.recommend()` and behind a CSRF-protected REST-only path. Restores the
   read-only MCP invariant that the `/mcp/**` CSRF exemption depends on. Consider extending the
   reflection read-only test to catch transitive write side effects.
3. **Remove `/h2-console/**` from the CSRF exemption and `permitAll`** (or gate strictly behind a dev
   profile) in `SecurityConfig.java`. *Human review required — protected file.*
4. **Add tests** for `AuthController`, `UserController`, `PlaylistController`, `UserService`
   (fail-closed 404), and `PlaylistService`.
5. **Scope `Bash(git push *)` to `fix/*`** in `auto-implement.yml`, and tighten the wildcard `Bash`
   grants in both workflows to the specific commands used.
6. **Guard `Retry-After` parsing** in `WebClientConfig.java` against non-numeric/HTTP-date values.
   *Human review required — protected file.*
7. Address MEDIUM/LOW items: switch `/quick` off GET for the state-changing path, validate `timeRange`
   and playlist `id`, add null guards in `SpotifyApiService.getOrCreatePlaylist` and
   `RecommendationService.recommend`, gate the daily placeholder job, and fill the Javadoc gaps.
